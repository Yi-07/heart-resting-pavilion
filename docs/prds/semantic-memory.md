# PRD · 语义级记忆检索

> 产品需求文档。描述「温层摘要升级为可检索语义记忆」的需求、方案与测试判据；只写本需求对现有管线的**改动面**。记忆分层机制权威源见 [architecture-spec.md](../architecture/architecture-spec.md)「L7 · 数据与知识层」，admin 端点契约见 [ws-contract.md](../architecture/ws-contract.md)；本 PRD 不复制其内容。

## Problem Statement

温层会话摘要 TTL 7 天后彻底灭失，长期只剩冷层每日心情。用户隔了话题或隔了周再提相关困扰时，线索接不上：三周前聊过「与室友闹矛盾、回避回宿舍」，如今说「晚上又不想回去了」，系统只能从心情曲线猜,接不住具体前情，用户须从头复述。

**用户视角问题**：跨话题、跨时间的因果线索断裂，陪伴连续性止步于 7 天。

## Solution

新增**语义记忆库**：collect 回合末异步把对话压成 30~60 字「检索笔记」写入独立 chroma collection（与心理知识库物理分离）；回答管线同步召回 top-3 相关笔记注入 collect/answer 的 prompt。温层原样保留平行双写，存量行为零改动。治理面板可查看记忆列表并单条删除。

弃型原型已验证可行性：跨话题弱线索该召回 5/5 进 top-3（4 例 top-1）；CPU 上召回链路延迟 median 63ms，同步召回可行。

## User Stories

1. 作为用户，我换了个话题再提相关困扰时，希望对方接得上之前聊过的前情，不用从头复述。
2. 作为用户，我希望已经化解的旧事不被当新困扰翻出来。
3. 作为用户，我希望在治理面板看到记住了哪些内容，并能删除单条。
4. 作为对话管线，我希望记忆库不可用时回合照常进行，召回只是增益不是依赖。

## Implementation Decisions

### 语义记忆库（新增）

- chroma 独立 collection（`hrp_mem_v1`，cosine），与知识库 `hrp_kb_*` **双向物理分离**：用户记忆不进知识库，知识检索不碰用户记忆。
- embedding 复用 bge-m3，与 rag engine 共享同一常驻实例，不双份驻留。
- 条目 schema：`text`（检索笔记，LLM 转述）+ metadata `{mood_label, intensity, status(open|settled), session_id, turn_index, date}`。**原文不落**——隐私红线「记忆粗摘要不存原文」延续，检索笔记同为转述。
- 写入覆盖仅 collect 回合：Finish 落定后异步生成检索笔记并入库，不碰回合时延；LLM 生成失败降级为 formulation 结构字段确定性拼接。
- **状态闭环**（原型暴露的设计点）：写入笔记时把本轮召回的 open 条目一并交笔记 LLM，输出「本轮化解了哪些」回写 settled；化解条目不再召回。LLM 临场否决保留为兜底，不再是主防线。

### 召回与注入（改 answer/collect 管线）

- 同步召回，复用 answer 路由 RAG 检索的就绪等待+失败降级模式。查询串 = 本轮输入 + 热层最近话题拼串（查询增强，模糊回指输入靠上下文补齐）。
- 取 top-3；噪声闸门低档：余弦相似低于常量（原型定标 ≈0.5）静默，不做高阈值硬卡——原型实测噪声顶点与真信号间隔过窄，硬卡会误杀；取舍权交注入后的 LLM。
- 时间衰减：超期（常量，原型按 30 天）条目降权。
- 注入点位：collect 的 Finish 总结（collect 侧唯一 LLM prompt 通道——追问为模板短语、研判为分类器）与 answer 的回答生成；两者都带「想起非翻旧账」指令,LLM 临场取舍。
- **红线**：召回注入在危机闸门判定之后；历史记忆不参与路由判定与危机判定，判定只吃本轮输入。本轮已判危机时，召回结果可供危机话术做延续关怀参考。
- 降级纪律延续 `memory/store.py`：全部读写异常吞掉记 WARN 不杀回合；`clear_all` 扩展为连语义记忆库一起清。

### 治理（admin + 前端）

- 新增 `GET /admin/memories`（记忆列表）与 `DELETE /admin/memories/{id}`（单条删除），进 ws-contract admin 端点表。
- 前端 admin 设置页新增「记忆列表 + 单条删除」——治理红线「用户可查看」须有 UI 兑现。

### 与温层关系

平行双写：温层 TTL 与 snapshot 回退路径零改动。语义库稳定运行后再评估是否取代温层（不在本需求内）。

## Testing Decisions

- 后端单测：条目写入/状态闭环回写/降级拼接、召回查询拼串、噪声闸门与时间衰减、`clear_all` 扩展、admin 端点；沿用 `test_memory` 真链路先例，需本机 Redis。
- 前端：admin 记忆列表组件单测 + 三件套全绿；后端三件套全绿。
- 真链路冒烟：collect 回合结束后语义库条目增长、次回合注入生效、`admin/memories` 可见可删。

## Out of Scope

- EmpathChat 与 answer 路由写入记忆（先原型观察，二期再定）。
- 温层被语义库取代。
- 温层结构化抽取（Mem0 方向）——另立项，与本需求正交，schema 加字段即可扩展，不做预留设计。
- 记忆库 BM25/重排（条目量级用不上）与多用户分区。

## Further Notes

- 原型证据钉子：不该召回组暴露纯向量不认否定与化解（「和室友已经和好了」仍召回矛盾条目）且存在效价反转（正效价输入拉近负向记忆）——这是状态闭环、噪声闸门、LLM 临场否决三层防线的依据；边界用例漂向良性（模糊回指自发靠向 settled 条目）。
- 设计前提事实：session_id 经前端 localStorage 持久、后端认领回放，单用户一条长寿会话链——语义记忆库单用户全局平铺（无分区）的前提。
- embedding 模型与知识库共用本地权重 `backend/models/bge-m3`，零新增依赖、零新增模型下载。
