# PRD · collect 链路体验重构

> 产品需求文档。描述 collect 链路「话术 LLM 化 + entry 即提取 + 打断清理 + 方案书自动生成」的改动面。机制与参数权威源见 [architecture-spec.md](../architecture/architecture-spec.md)「三路路由」「L4 · 空窗期策略」「L5 · 异步推理层」；消息契约见 [ws-contract.md](../architecture/ws-contract.md)「3.1 first_frame」「6.2 collect」「8. 错误处理」；本 PRD 不复制其内容。裁定来源：collect 链路检查会话（2026-10-10/11，Q1~Q10 逐项裁定，台账 V2.11）。

> **完结注（2026-10-12）**：五面改动全部落地（T1~T8，commit `db7b587`..`0cdb79d`）。实现与裁定的两处偏差：① entry 即提取不跑降级检测（too_short/negative 是问句回答的轮次机制，首条输入无此语境）；② 方案书历史保留的查询 API/前端预览按 Non-Goals 未做。验收判据 7 条全过（后端 ruff/mypy/pytest 222 过，前端 type-check/lint/test:unit 126 过）。

## Problem Statement

collect 链路现行体验三处硬伤：

1. **话术无人味**：问话/确认语/陪聊全走预置库，句式雷同、重复会话逐字一致；off_topic 陪聊固定一句；「正在把你说梳理进黑板」等文案与实际动作错位；「右侧的心灵补给站」方位与实际入口（顶部工具栏）不符。
2. **首条输入利用率低**：entry 只把快速研判标签放进 emotion，用户首条输入里的实质信息（情境/念头）要等第 2 条输入才被提取；粗稿（scene_default 无字段槽位）画不出任何用户内容，板式切换（需实质字段入格+有效选材图标）最早发生在第 2 轮——黑板「陪你慢慢长」的观感不存在。
3. **打断/等待感知错位**：collect 问话全程无语音（逐句 TTS 只在 answer 路）；轮次回答/done 后的旧语音残留靠「下一回合音频首块自认领」兜底，无音频的新回合旧声播完为止；问话 LLM 失败无用户可见信号（预置问句静默兜底反而掩盖错误）。

## User Stories

1. 作为用户，我希望小栖的提问像正常对话一样自然变化，而不是每次都听到一模一样的问卷腔。
2. 作为用户，我希望说完第一句就能看到黑板开始画我说的事，而不是等第二轮。
3. 作为用户，我希望提问有声音（逐句 TTS），文字与语音一起到，而不是只有文字。
4. 作为用户，我说话时希望旧的语音立刻让位（淡出），而不是旧声新文并存。
5. 作为用户，生成遇到问题时我希望看到明确的系统提示（辐条），而不是一句假装正常的预设话术。
6. 作为用户，我读完总结点开心灵补给站时，方案书应该已经在生成或已就绪，而不是从零开始等。

## Solution

按裁定分五面（每面的机制细节以权威文档为准，此处只记改动面与验收口径）：

### 1. 问话 LLM 化（Q2/Q5/Q6/Q10）

- 问话从预置话术改为 LLM 流式生成（`provider.stream`），与提取拆为两次调用：提取（chat_json，出 fields/assets）→ 问话（stream，出文本）。文字攒批发 text_delta + SentenceSplitter 逐句 TTS，与 answer 句子泵同构复用。
- 系统提示词规范共情陪伴者风格（建议式、口语化、不做医疗诊断）；已采字段与剩余轮数进 prompt（进度感知由对话自然带出）；语义记忆召回注入问话 prompt（spec「语义记忆检索」已列问话为注入通道）。
- 预置问题库（`collect/questions.py`）降级为字段选择/问序的内部结构单源，不再作对外话术。
- 失败处置：问话 LLM 失败 → `error(ask_llm_failed)` → 前端辐条；采集态挂起（pending_question 保留），下一条输入重试。**不发预置问句兜底**（裁定：不掩盖错误）。
- off_topic 陪聊轮同走 LLM 流式+逐句 TTS（`EMPATH_CHAT_REPLY` 固定文案废弃）。
- AskNext 事件形态变更：`confirm` 字段取消（确认语由问话流自然带出），事件携带 `question + target_field`。

### 2. entry 即提取（Q1 + 粗稿裁定）

- 首条输入过路由即跑字段提取+选材（现 extract 逻辑提前到 entry 跑一次），粗稿带实质字段与选材图标出图；板式接力条件不变，时点提前至 entry 即可发生。
- first_frame.text 置空（开场不设安抚语）；安抚语 TTS 任务（`_speak_if_current`）、`SOOTHE_BY_LABEL/SOOTHE_CARRY/collect_soothe` 整体移除。
- entry 提取 LLM 失败降级：回退旧行为（只填研判标签进 emotion），不阻断回合。

### 3. 预置话术收敛 + 预置语音（Q7/Q8/Q9 + 文案裁定）

- **保留的预置话术**（预生成 wav 随文同步播，fillers 机制扩成通用「话术→wav」表，GPT-SoVITS 同音色重跑）：
  - 等待语音（P7）：文案改「嗯，好的，我已经大体了解了你目前的状况，让我来好好地帮你梳理一下，共同探索缓解的方案」
  - 危机安抚（P10）：文案改「我知道你现在一定非常痛苦，我们先将我们冲动的情绪稳定下来，深呼吸，我永远站在你的身旁，与你一起度过难关」
  - 危机热线（P11）：文案改「如果你还是很难受，你可以拨打全国心理援助热线 12356，或者告诉身边一位你能信任的人，你的背后是这个温暖的世界。」
  - 危机黑板注（P12）：改「加油！你能行的」
  - 心情回执（P13，六档）：难过→「抱抱，难过的时候确实需要陪伴，我陪着你。如果你愿意的话，可以跟我说说发生了什么；不想说也没关系，我就在你的身旁。」低落→「嗯，心情低落确实不好受。需要和我聊聊吗？不想说，我陪你安静待着也好。」平静→「平静挺好，给自己留一点这样的时刻也很不错。想聊聊天吗，随便聊聊也行，我挺想听。」还好→「还好就好，慢慢来。这个"还好"是轻松了一点，还是心里还有一点事？愿意的话，可以和我讲讲，我听着。」开心→「今天心情不错呀，有什么开心事和我分享分享，独乐乐不如众乐乐，让我也替你高兴高兴。」很好→「真好呀，把这份好心情多留一会儿。快和我说说，是什么让你这么开心？我想听，也想沾沾你的好心情。」
  - 邀请语（P8）：保留机制，去方位词——「我把这次的梳理放进了「心灵补给站」，里面有一份为你整理的小方案，想看的时候随时点开。」
- **废弃**：确认语/重试语/陪聊固定文案（LLM 化）；SUMMARY_FALLBACK 保留话术性质（Q9 裁定：对话内容不走辐条）。
- 总结 prompt（`summary_messages`）user 段剔除数值类字段（intensity 不进 prompt，防百分比混入人话总结）。

### 4. 打断清理（Q3/Q4）

- 前端 user_sent（本地事件，零协议改动）即 flush 旧回合音频；first_frame 的 flush 保留。
- flush 加淡出：PcmPlayer ~120ms gain ramp 淡出；新回合首块 ~50ms 淡入（防爆音）。AudioHub 统一。
- 服务端打断基建（round 级 CancelToken + `/v1/tts/cancel` cascade）已由 tts-pcm-streaming 任务线落地，本任务只补前端触发点与淡出淡入。

### 5. 方案书回合末自动生成（方案书裁定）

- 生成触发从「用户点击」改为「Finish 归档时后台自动启动」（挂 `_archive_round` 同批，done 照发不等待）；`POST /station/report/generate` 保留为手动重生成入口，前端取稿轮询不变。
- `station_reports` 表加 `round_id` + `emotion_label` 列（主键改 `(session_id, round_id)` 历史保留）；查询 API/前端预览**不做**（backlog 入池）。
- 邀请语时机不变（总结末尾）；危机回合不产素材、409 语义不变。

## Non-Goals

- 方案书历史查询 API 与前端预览（backlog）
- 流式 JSON 协议（方案 C，理论延迟最低但工程风险高，二期再议）
- 黑板「采集进度」占位提示件（Q10 裁定：进度感知由问话对话承载）
- 危机话术正文进契约（正文归 phrases.py 单源，契约只记机制）

## Acceptance Criteria

1. 新会话首条输入「最近被 leader 当众否定了，很焦虑」→ first_frame 后黑板上出现情境/情绪字段与图标（entry 即提取生效），随后问话文字流式上屏、语音逐句播出。
2. 连续两轮回答内容相近 → 两轮问话文本明显不同（LLM 生成非预置）。
3. 断开 LLM 服务后发轮次回答 → 前端辐条提示出现、对话气泡无假话术、服务端 WARN 日志（`ask_llm_failed` 相关）；恢复后下一条输入采集继续。
4. 轮次回答提交瞬间（user_sent），旧回合残留语音 ~120ms 内淡出。
5. 回答完成 done 后点开心灵补给站 → 状态为 pending 或 ready（自动生成已启动），非「无历史记录」。
6. 人话总结文本不含「xx%」式强度百分比。
7. 全量检查过：`uv run ruff check app && uv run mypy app && uv run pytest`；`npm run type-check && npm run lint && npm run test:unit`。
