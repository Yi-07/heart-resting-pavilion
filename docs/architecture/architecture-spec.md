## 1. 项目概述

面向轻中度情绪困扰人群的情感陪伴 + 心理知识科普工具。**明确不提供医疗诊断**，仅辅助支持。

- **产品形态**：引导式对话，不是回答机器——不等用户一次给完整答案，按节奏分多轮梳理
- **交互**：打字/语音双输入（语音走录音→ASR→文字）+ Live2D 立绘 + 黑板可视化 + 语音播报
- **智能**：多 Agent 协作（LangGraph）+ 动态 RAG + 危机安全闸门 + 多轮采集（CBT 认知概念化）
- **目标**：中国大学生计算机设计大赛（AI 算法创新 · AI+软件）+ 个人 AI Agent 开发求职作品集

## 3. 三路路由

```
用户输入（user_input / mood_select）
  → L3 危机闸门（规则硬判，作用于每条 user_input）
      ├─ 命中 → crisis：热线 12356 + 支持性黑板 + 降级安抚 [中止采集]
      └─ 未命中 → 分类器：{route: answer|collect, emotion_label, confidence}
           ├─ answer（简单+知识）→ 直接答：知识走 RAG，普通问候直接生成；不问用户、无黑板、无采集
           └─ collect（情绪梳理）→
                L1 第一帧安慰语（user_input 后 ≤300ms 必达，按情绪标签选文案）+ 心情选择器浮出（非阻塞）
                L1 粗稿模板绘制（用快速研判标签）
                L4 多轮采集（上限 3 轮，每轮问话由 L5 共情 Agent 出，L4 只管状态）：问 → 答 → 危机闸门再查 → 填 formulation → 黑板增量补字段
                    充分度 ≥0.7 或轮数上限 → 停止采集
                    降级触发（答案过短/话题漂移/负面词）→ 三降级路径
                L5 分析完成（RAG + 多 Agent）
                L1 精稿绘制（完整 formulation）+ 补笔收尾动画
                → Live2D 人话总结（末尾拼"心灵补给站"邀请语）
                    〔用户点击心灵补给站 → planner 异步生成方案书（懒生成，REST 通道）〕
                L7 记忆：心情自我报告 + 对话摘要 → 情绪趋势
```

## 4. 容器规格（C4 Container）

### L1 · 用户交互层

- **职责**：情绪表达与治疗性可视化前端，把「理解」变成看得见的黑板画面
- **关键机制**：情绪一源三用（同一 emotion JSON → Live2D 表情 / 黑板情绪字段 / TTS 情感标签——TTS 侧为接口预留，现行未接线）· 黑板由模板声明+通用渲染器构成 · 心情选择器 · 语音可插拔 + 模型配置 UI
- **数据契约**：输入为 user_input / mood_select；输出为 first_frame / text_delta / draw / audio_chunk / done

**组件**：

| 组件 | 职责 | 契约 |
|---|---|---|
| 黑板·模板渲染器 | 按模板声明布局：静态素材层 + 动态数据层（锚点叠加）| 模板声明 {asset， fields} + draw 数据 |
| 黑板·粉笔效果 | 直线中点抖动 + 二次贝塞尔；圆半径噪声；dash-reveal + 粉笔光标；feDisplacementMap 只套图形不套文字 | 渲染层，保标签可读性 |
| 心情选择器 | 空窗期主动浮出（非阻塞）、6 档粗粒度、10s 超时自动收起、危机时不浮出 | → mood_select 上报 L7 |
| Live2D 立绘 | 情绪表达载体（MVP 直接上）| 情绪 JSON → 表情参数 |
| 语音 I/O | 录音采集/音频播放（ASR/TTS 引擎执行在 L6）| 录音→base64 上传；播放音频块 |
| 聊天区 | 文字/语音输入 + 气泡 + 流式文本 | — |

### L2 · 接入与网关层

- **职责**：一条可靠连接承载整个流水线；实时感由应用层实现
- **数据契约**：**9 种消息**（JSON 文本帧）：S→C `first_frame / text_delta / draw / audio_chunk / done / replay / error`；C→S `user_input / mood_select`（消息格式唯一记录处见 [ws-contract.md](ws-contract.md)「消息总览（9）」）

- `draw.seq` 递增：前端增量绘制 + **中断判定**（新请求 seq 更高 → 作废旧画面，开启新回合）

### L3 · 智能路由决策器

- **职责**：安全前置：危机信号第一时间被确定性规则捕获，一条消息三种去向
- **关键机制**：危机闸门（规则硬判，目标 ≤10ms/条——纯本地词典+打分，无 LLM/网络调用；作用于每条 user_input）· 分类器**分层判定**（复用规则引擎，零新增组件）：规则先判明显 case（问候、知识词表命中）→ 模糊才调 LLM 拿 `{route, emotion_label, confidence}`；规则路径 conf 记 0.9（可调常量）；LLM conf < 0.6（可调常量）→ 兜底 collect（collect 比 answer 安全：错了只是多问一句）· RAG 门控复用同一分层判定。**实现态注记**：LLM 分支为设计态，网关现行只走规则路径（未接线）；规则全不命中走 fallback 分支直接进 collect，conf 记 0.0
- **隔离约束**：**crisis 与 route 走规则/确定性判定；emotion_label 只喂黑板/Live2D，绝不进路由**
- **两级标签**：快速研判（粗稿）+ RAG/LLM（精稿）；优先级链：用户选择 > 关键词研判 > 中性兜底

### L4 · 空窗期策略（横切编排）+ 多轮采集器

**空窗期策略**（横切编排：横切是分布方式，编排是职责）：
- **职责**：等待即治疗 + 引导式梳理，把空窗期转化为治疗过程
- **关键机制**：第一帧缓冲（user_input 后 ≤300ms 发出 first_frame，安抚语先行；模糊输入分类器 LLM 未返不等待，按 collect + 中性兜底标签先发；LLM 后到不撤回，仅精化 emotion_label）· 黑板渐进绘制（协同 L1）· 语音安抚（协同 L1）· 流式增量（Agent 回调）

**多轮采集器**：状态机 / 充分度 / 轮控，**管状态不管话术**（问话归 L5 共情 Agent）

**采集器规格**：

| 项 | 值 |
|---|---|
| 轮数上限 | 3（可调常量；充分度 0.7 常态 2 轮收尾）|
| 问题生成 | 预置问题库按最高优先级空缺字段选，LLM 仅润色贴合上文（骨架由预置库供）|
| 分析触发 | 充分度 ≥0.7（可调常量；测试档 0.85 时约 3 轮挖信念）或轮数上限 → STOP → 停采后同步分析 |
| 分析就绪线 | 充分度 ≥0.4：二期后台分析启动线，MVP 无操作语义 |
| 降级触发 | 答案过短 / 话题漂移 / 负面词 → 三降级路径 |
| 中断 | 新请求 → 依据 draw.seq 作废旧画面，开启新回合 |

**三降级路径**：
1. 停止采集 → 转共情陪聊
2. 粗稿 + 已采字段收尾
3. 情绪明显变差（**操作化：软预筛词典低档位命中 或 formulation 情绪强度环比上升**；环比检测属二期，现行只走软预筛词典路径）→ 再过闸门（危机转热线）

### L5 · 异步推理层 · 多 Agent

- **关键机制**：条件边门控（确定性；risk 复核为唯一 LLM 验收点）· 共情前置（采集话术由 L5 出）；编排载体为 LangGraph StateGraph（选型见「技术栈」）

**Agent 名单**（本表为唯一权威，余处只引用）：

| Agent | 职责 | 激活 |
|---|---|---|
| 共情陪伴者 | **采集话术为确认情绪 + 下一问**；分析后组织人话总结；建议式非命令式 | collect 全程 + 分析阶段 |
| 知识分析师 | 动态 RAG：需不需要查 → 需要才走 Chroma+BM25+重排 | 门控判定 |
| 风险评估者 | 规则硬判 + **软信号关键词预筛** → 仅命中才 LLM 复核 | 每轮预筛 / 命中复核 |
| 计划制定者 | 基于完整 formulation 生成心理成长计划/练习建议；**安全边界为非医疗声明 · 危机绕过 · 方案基于 RAG 知识不凭空编**；产物为心灵补给站方案书 | 用户点击“心灵补给站”触发（异步） |

### L6 · 工具与执行层

| 组件 | 职责 |
|---|---|
| RAG 引擎 | Chroma 向量 + BM25 关键词 + 重排序（咨询/风险才检索）|
| 规则引擎 | 危机词典/分级/降级话术库，**与 L3 闸门共享单一词典来源**，职责不重复 |
| 语音引擎 | TTS=CosyVoice 2（本地；情感标签属接口预留，现行未接线） · ASR=SenseVoice（FunASR，本地，含情感识别），接口化可插拔（ASR/TTS 执行端）|
| 计划工具 | 日历 / 量表（供计划制定者调用）；二期 |

### L7 · 数据与知识层

| 层 | 内容 | 存储 | 生命周期 |
|---|---|---|---|
| 热 | 当前会话上下文：摘要 + 最近轮次原话（≤20 轮，供重连重建与回放，ADR-001/005） | Redis | TTL 30min（原话到期即弃构成隐私边界，中长期只留摘要） |
| 温 | 会话摘要（粗摘要不存原文）| Redis | TTL 7天 |
| 冷 | 长期画像 + 情绪趋势（每日心情记录 `{date, mood_label, intensity, source: mood_select/研判}`）| SQLite | 无 TTL |
| 外挂 | 心理知识问答对，供 RAG | Chroma | 与用户记忆分离 |

**治理层**：Key 隔离 + 版本号 · 音频不落库 · 用户可查看/一键清除。
**模型配置存储**：LLM/ASR/TTS 引擎配置，AES-GCM 字段加密存 SQLite；密钥环境变量注入不入库；前端零密钥；日志脱敏。

## 5. DrawProtocol

### 5.1 draw 消息

```json
{
  "type": "draw",
  "seq": 2,
  "template": "beck_formulation",
  "data": {
    "situation": "被 leader 当众否定",
    "emotion": { "label": "焦虑", "intensity": 0.85 },
    "thought": "我不行",
    "behavior": "逃避会议",
    "intermediate_belief": null,
    "core_belief": null
  }
}
```

- `seq` 递增：增量绘制 + 中断判定
- 后端只发语义数据，**前端按模板声明算坐标（后端零布局）**

### 5.2 模板声明结构（前端）

模板由**静态素材层 + 动态数据层**构成。素材层为预制 SVG 插画；数据层字段通过锚点挂在素材上。

```json
{
  "id": "beck_formulation",
  "asset": { "src": "/assets/beck/tree.svg", "zone": "full" },
  "fields": [
    { "key": "situation", "anchor": "asset#root",  "widget": "text" },
    { "key": "thought",   "anchor": "asset#trunk", "widget": "text" },
    { "key": "emotion",   "anchor": "asset#canopy", "widget": "highlight" },
    { "key": "core_belief", "anchor": "asset#soil", "widget": "text" }
  ]
}
```

- 无 asset 时退化为纯几何模板（初期 MVP 用）
- **定制模板只需加一份声明，前端渲染器 / 后端链路零改动**
- **字段 key 必须与 formulation 字段名一致**（`situation/emotion/thought/behavior/intermediate_belief/core_belief`），与 `draw.data` 对齐；belief 是两个字段（intermediate/core），不设概括名
- **anchor 两种形式**：`asset#<id>`（素材模板，锚在素材 SVG 上）· `zone:<name>`（纯几何模板，无 asset 时锚在声明布局区）；渲染器按类型解析

## 6. formulation schema（Beck 认知概念化）

| 字段 | Beck 对应 | 黑板绘制 | 采集轮次 | 权重 |
|---|---|---|---|---|
| situation 情境 | 触发情境 | 顶部椭圆 | 第 1 轮 | .20 |
| emotion 情绪+强度 | 情绪反应 | 情绪轮盘 | 第 1 轮 | .20 |
| thought 自动思维 | 自动思维 | 中部椭圆 | 第 2 轮 | .20 |
| behavior 行为 | 行为反应 | 旁注 | 第 2 轮 | .15 |
| intermediate_belief 中间信念 | 规则/假设 | 底部逐轮补 | 第 2~3 轮 | .15 |
| core_belief 核心信念 | 核心信念 | 底部最深 | 第 3 轮 | .10 |

- **充分度**取已填字段权重和（全填即 1.0；emotion 计入，label 必有、intensity 可 null）
- **默认 0.7**：常态 2 轮收尾；信念字段（中间/核心）为 bonus，仅高配合或阈值上调至 0.85 测试档才采集
- **绘制**为同一张图增量填字段（表层→深层），不换模板
- **作用链**：每轮问什么取最高优先级空缺字段；黑板每轮画新采字段；分析触发为充分度达标

## 7. 心情选择（今日心情）

| 项 | 值 |
|---|---|
| 触发 | 空窗期主动浮出（立绘旁/黑板下沿），非阻塞 |
| 粒度 | 6 档粗粒度（难过/低落/平静/还好/开心/很好）→ 映射主情绪词表 |
| 超时 | 10s 未点自动收起，回退研判结果（前端可调常量，演示 10s）|
| 上报 | `mood_select` → L7 冷层 profile 情绪趋势；通常在第一帧后、第 1 轮回答前到达 |
| 联动 | 选择后立即切 Live2D 表情 |
| 例外 | 危机时不浮出 |
| 独立到达 | 用户未说话先主动选（无活跃会话）→ 仅更新 L7 profile + 触发 Live2D 表情，不进入采集 |

## 8. 危机分支

- 危机闸门（规则硬判）作用于**每条 user_input**（answer/collect 路径均先过闸门再分类；采集轮次的回答同样是 user_input，故每轮受检）
- mood_select 不经过闸门（6 档枚举，无自由文本）
- 任一命中 → 中止采集 → 热线 12356 + 支持性黑板画面 + 降级安抚
- 软信号（未达硬判阈值）→ 风险评估者预筛命中后 LLM 复核
- 危机判定只在后端 L3；前端零危机逻辑

## 10. 开发范围（MVP vs 二期）

**MVP**：三路路由（answer/collect/crisis）· 危机闸门贯穿 + 热线 · 快速研判（分类器标签扩展）· 多轮采集 + formulation · mood_select · 停采后分析（同步；后台并行留二期）· 黑板模板声明渲染器 + 粗稿/精稿 · 心灵补给站（方案书懒生成 + md 预览/导出）· 语音链路（打字/语音双输入）· 记忆最小闭环 + 治理层 · 模型配置 UI · Live2D（情绪一源三用）。

**二期**：多模态节奏协同（黑板/语音/Live2D 编排）· WebRTC 打断式语音 · 知识图谱（knowledge.query 接口缝）· 语义级记忆检索 · 黑板模板库定制扩充 · ASR 强化 · 多人并发 · Tauri 打包。（完整二期见 `ARCHITECTURE_PROGRESS.md`「二期范围总表」）
