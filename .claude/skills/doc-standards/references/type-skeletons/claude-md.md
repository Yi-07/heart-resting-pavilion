> 行数硬约束:官方建议单文件 <200 行,社区共识 <300 行;超 4 MiB 整文件被跳过;常驻链(含 AGENTS.md)合计目标 ≤100 行。指令预算:模型可稳定遵循约 150-200 条全局指令,遵循力随总数均匀衰减,每加一条稀释全部。多工具并存时做 AGENTS.md 副本,头部注真源。

**收录判据**:删了 agent 会出错才收;猜得出/可推导/标准语言惯例/详细 API(改指针)/频繁变化/长教程/逐文件描述/「write clean code」类自明话全拒。具体可验证指令优先:「2 空格缩进」而非「格式规范」。IMPORTANT 类强调全文至多一处;什么都强调等于没强调。

**节集**(按需取,不硬齐):
- 项目一句话+文档指针表:每份一行(位置/性质/触发场景);指针前置于行首触发词,一个分支一个触发词,同义合并
- 边界表:新代码落点/旧代码禁区
- 核心约定:机制级强制规则,编号,可执行
- 开发命令:分端(目录前提/包管理器);环境可自查的不写,写查不到的(端口/env/包管理器);注释两分法——携带命令查不出的新信息(何时跑/前置/边界)才注;验证路由一行原则(按改动面选跑,不全套跑)
- 风格红线:仅收异于默认值且 linter 管不了的(契约对齐/脱敏/安全);风格规则优先交 linter
- 排除:changelog/历史/目录树导览(实证对 agent 导航无助且易腐烂)/自动生成内容(实证使任务成功率下降)

**迭代**:同一错误第二次出现才加规则,第一次口头纠正;违规屡犯是文件过长的信号;环境真源(package.json/config)只缓存查不到的:约定、原因、坑。
