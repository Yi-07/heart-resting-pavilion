# CONTRIBUTING 骨架(贡献者协作规则)

> 触发器:团队协作规则成型(与 README 同批建立,README 协作节拆出至此)。读者是动手改代码的人,窄受众;README 管「是什么/去哪看」,本文件管「怎么参与」。GitHub 对 issue/PR 自动提示本文件。

**写作纪律**:对「你」说话,零 agent 指令句,逐句体检「这句在指挥谁」——「停下问人」类归 agent 入口文档;信息呈现式写法(见 human-style 第 5 节),规则直接开头,不架「与 agent 协作:」类框架;黑话换白话:「单源」改「细则见」、「红线」改「工程纪律」、看板词带白话括注;纪律条目写「不允许/不得/要」,不写紧缩否定;次要说明走 `> [!tip]` callout。

- 环境搭建:指向环境/操作手册,逐步骤
- 分支与提交:分笔纪律(不同源改动分笔)+提交信息惯例
- 验证路由:改后端/前端/文档各跑什么检查(与 agent 入口同源的人声复述;双渲染各说各角色,不混声)
- 文档纪律:契约先改契约文件再改两端,同批提交;公共行为改动核 spec 同步;新代码落点边界
- agent 管控(对人的条目):监控 agent 操作、保留人工检查点;agent 规则入口是 CLAUDE.md,队友开 agent 前先读
