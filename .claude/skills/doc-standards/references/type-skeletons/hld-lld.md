# HLD/LLD 骨架(架构 spec / 实施方案)

> HLD=系统级(机制/参数/边界),只读权威源,先于代码存在=设计源;LLD=按端实施,记模块职责与接口——文件真源=文件系统,文件增删改不回 LLD,职责变化才改行。

**HLD(spec)**
- 路由与安全模型(铁律+隔离约束)
- 数据模型(字段语义;数值单源声明=此处)
- 分层职责(每层管什么/不管什么)
- 性能与成本热点
- 二期边界(指针到总表,不复制)

**LLD(plan)**
- 目录风格法则(一职能一深模块目录;文件不散放根)
- 模块职责表:模块/职责/关键接口——接口相关事实留接口列,纯实现细节代码落地日入 docstring、同 commit 出表
- 关键签名(接缝:小而完整+错误模式写明)
- 与契约对齐声明(类型单源=契约文件)
