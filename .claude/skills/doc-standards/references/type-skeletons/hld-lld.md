# HLD/LLD 骨架(架构 spec 与实施方案)

> HLD 管系统级:机制/参数/边界,是只读权威源,先于代码存在,充当设计源。LLD 按端实施,记模块职责与接口;目录真源在文件系统,文件增删改不回 LLD,职责变化才改行。数值与端点以 spec 为单源。

**HLD(spec)**
- 路由与安全模型:强制规则与隔离约束
- 数据模型:字段语义,数值单源声明在此
- 分层职责:每层管什么,不管什么
- 性能与成本热点
- 二期边界:指针进总表,不复制

**LLD(plan)**
- 目录风格法则:一职能一深模块目录,文件不散放根
- 模块职责表:模块/职责/关键接口——职责写本模块自身做什么与数据落点,不枚举调用方(那是对方职责);接口相关事实留接口列,纯实现细节在代码落地日入 docstring,同 commit 出表(一步搬家)
- 关键签名:接缝小而完整,错误模式写明
- 与契约对齐声明:类型以契约文件为单源
