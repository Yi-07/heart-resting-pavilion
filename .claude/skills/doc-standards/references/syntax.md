# 句法与记号硬规则(syntax)

> 收尾 grep 四查的判法源,也是动笔时的句法约束。档位:交付文档全量适用;执行状态文档(kanban/handoff)与 skill 自身适用记号纪律与语域豁免(标点体例待裁,见第 6 节);研究记录仅避用词。

## 1. 中文句法红线

- 单句不超过 40 字,逗号分隔短句不超过 30 字,超长拆句;不用复合句和多层嵌套从句。
- 主动语态。禁「被/受/遭」被动句式(描述系统自身行为的三类例外:强调对象/弱化责任者/纯系统行为,可保留被动)。
- 肯定句。禁双重否定。
- 条件前置:条件写在动作前;「如果不X就Y」改写为「必须X才能Y」或「X 则 Y」。
- 先定位后动作:先说在哪,再说做什么。
- 代词克制:该/此/其/它少用;指代对象上一句出现过的,本句重复具体名词。
- 名词前定语超过 2 个,拆成列表。
- 去形容词:主观形容词与副词(强大/高效/无缝/完美/极大)删,换可数事实或数据(「查询快」改「查询耗时低于 50ms」)。
- 步骤类内容用有序列表,每步一个动作,动词开头。
- 禁比喻、类比、打比方;法则表述改直白动词句。
- 禁感叹号、反问句、排比(连续三句同结构)、八股过渡(首先/其次/最后)。
- 一个意思只说一遍,不换说法重复。

## 2. 禁词表(避用词 grep 判法)

**跨语域病文风词**(交付文档、工作文档全禁):
值得注意的是 · 需要指出的是 · 不难发现 · 此外 · 另外 · 与此同时 · 在此基础上 · 旨在 · 赋能 · 抓手 · 闭环 · 打通 · 从而 · 进而 · 继而 · 确保 · 保障 · 综上所述 · 总而言之 · 总的来说 · 让我们 · 我们不妨 · 一眼可辨

**语域禁词**(交付文档禁;agent 声工作文档 kanban/handoff/skill 合法):
停点 · 销账 · 落定 · 交付批 · 接力 · 开新窗 · 收尾窗口 · 落地 · 落位 · 落盘 · 口径 · 三件套 · 黑盒 · 钉死 · 全绿 · 必炸 · 丢入 · 一次拉起 · 锚定 · 沉淀

语域判据:「换成任意成熟 OSS 项目的同类章节,这个词不会出现」即禁(按交付文档语域套)。替换方向:中止操作并向维护者确认 / 唯一记录处 / 以……为准 / 向维护者汇报。

**人读文档黑话翻译**:单源改「细则见」(「为单源」仅限头注元层声明,正文指针写「唯一记录处见X/细节见X」);红线改「工程纪律」;看板黑话带白话括注(「执行状态(任务看板)」);行为指令句(停下问人类)归 AGENTS.md,人读文档残留即删。

**「单源」用词分层**(全语域):头注元层声明「本文是 X 单源」合法;正文指针一律「唯一记录处见X/细节见X」。

grep 豁免:代码围栏内、行内代码字面量、术语表正词条。

## 3. 记号纪律

- 箭头「→」三处合法:表格导向列、行内 code 事件时序、text 围栏流程;正文散文零箭头链。表格内病型到处方的指向(消歧列)按导向列对待,合法。
- 等号「=」:正文零等号,映射与定义用语言写完整句(「术语表收词是什么和用哪个」,不写「术语表=词是什么」);豁免仅 code 语境(代码字面量/命令/判定值域)。
- 粗体:只标改变行为的子句(如「不落原文」「必落审计日志」);条目标签、节标题不加粗。
- 裸 § 节号禁用:节引用写节名(人读文档必带跳转链接,如「见『改动后验证』」);节号会漂移,对读者无意义。全语域适用。
- 标点:交付文档全稿全角(，：；（）「」),代码字面量与围栏内豁免;正文括注用全角括号,半角括号与半角分号混排清零。
- 链接分层:常驻链(CLAUDE.md/AGENTS.md)指针一律反引号路径零链接(链接只服务人,纯增 token);其余全部文档指针加跳转链接;指针导引必带跳转链接。
- 状态符号:表内用 Unicode 几何符号(✓ 已完成 · ✗ 不支持 · ⚠ 注意事项 · △ 可选/部分支持);表外状态用大写文字标签加方括号([TODO]);emoji 不用。
- 环境参考写本机实测值并随轮刷新;验证列必须是可执行命令,不可验证的 GUI 描述(「鲸鱼图标稳定」类)禁入表格。
- 墓志铭:日期/版本链/commit 哈希/阶段标记不落交付文档,归 git 与进度台账;执行状态文档勾选条目压一行结论句(结果值+落点),怎么落的归 git log。
- 英文词混入:人读文档正文零英文词(技术 token 与命令豁免);agent 声文档技术术语英文合法。

## 4. 载体判据

- 一列说得清用列表;必须行乘列表达对应关系才用表格;有序列表需顺序论证(流程步骤/优先级),无序为默认;单列表信息过载即拆分。
- 列表 2 至 7 项;单个条目不成列表。
- 平行结构:同级条目同一语法形态。
- 命令载体:bash 围栏加语言标注加行内 `#` 注释;命令语义(何时跑/前置条件/适用边界)全进注释;禁裸命令进正文。注释携带命令查不出的新信息才留,复述命令字面义的删。
- 标题:任务型动词原形开头,概念型名词短语;标题即大纲,标题下不复读;标题末尾无句号;层级不超过三级。
- 章节开头第一句是结论或操作指令,不写引言;每段一个点,段间无过渡句。
- 阈值句:阈值加溢出动作或工具后果,只收紧不放宽;门禁表三列(工具/时机/失败后果)。
- 前置条件与注意事项单独用引用块或 ⚠ 标注,不混正文;弱起句禁(「有」「你可以」起手)。
- 指令可执行五要素:前置条件/命令/预期结果/失败恢复/验证方法(操作手册类逐条配齐)。

## 5. 消歧与情态(Google/Microsoft 规范可移植子集)

- 术语一致性:同一事物只用同一个词;CONTEXT 正词不可换写法。
- 空态不自述:空节/空态不写「暂无/尚无」类自述文字,留位本身说明一切。
- 职能自述不作管教口吻:「不在此管」写「不在此过多叙述」。
- 禁拟人化:软件不「看见」「告诉」「想要」。
- 禁最高级与绝对词(best/simplest/never/always);有例外就写明例外条件。
- 时间锚定词禁(currently/now/latest/目前/现版本)——文档 timeless,时态信息归 git;「未实现」类状态注记不属此列。
- 输入中性动词:界面操作手册用「选择/输入/清除」,不用绑输入法的动词。
- 情态三档不可混用:必须(requirement)/建议(recommended default)/可以(optional)。
- 主张可证:兼容/安全/性能声明链接维护中的证据,不写无据断言。
- 链接是认知负荷:页内自足优先,引用外部文档时给能力描述而非裸路径。
