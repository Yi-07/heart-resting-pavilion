# 文档规范判据(写/改/审与缺位生成)

> 本文件是操作单源,含分叉、流程、判据表、信息路径模型与写作杠杆。细则按需读:句法与记号硬规则见 `references/syntax.md`;图表判据见 `references/diagrams.md`;人向文风见 `references/human-style.md`;裁定先例见 `references/cases.md`;骨架库见 `references/type-skeletons/`。

## 适用分叉(先定档位)

| 档位 | 覆盖 | 约束 |
|---|---|---|
| 交付文档 | spec/方案/契约/CLAUDE.md/AGENTS.md/README/操作手册 | 判据表与句法全量 |
| 执行状态文档 | kanban/handoff/progress 台账 | 记号纪律、墓志铭判据、避用词;日期叙事合法(判据 1/9 豁免) |
| 研究记录 | 调研笔记/分析报告 | 避用词;日期叙事合法;其余酌情 |

拿不准档位时按交付文档处理。

## 相位分叉(再定入口)

- 用户点名要写/改某文档:直接走执行流程,不弹缺项清单
- 用户不知道该建什么、要求盘点文档或新建项目搭文档:走生成流程

## 生成流程(盘点缺项时)

1. 扫触发器:逐型过两问——项目什么状态?谁要用?对照核心型录;存在性 ls 核验,不凭记忆
2. 呈缺项清单:一行一型,附触发器命中理由;触发器不命中就不算缺项,不建
3. 用户点头才动笔,不静默铺文档
4. 每份新文档一行建档,四项:读者(人/agent/双)、寿命(常驻/长命/活态/短命)、单源边界(管什么)、退场规则(何时删)
5. 照 `references/type-skeletons/` 对应骨架逐份生成;人向文档过表达三问(想传达什么/给谁/如何传达),核心表达逻辑获确认才写正文
6. 收尾走执行流程第 4 至 6 步

生成流程完成判据:缺项清单获点头;每份产物过骨架全节和判据自查;grep 四查零命中。

## 执行流程(写/改/审时)

1. 定档位(适用分叉);agent 向文档判读者档(常驻/按需),人向文档判声部(信息路径模型)
2. 人向文档动笔前过表达三问,核心表达逻辑呈确认;不确认不写正文
3. 逐段套判据表,分删/留/改写,每处改动记一句话理由——**删了行为会变吗?** 不变就删;会迫使 agent 猜的必留
4. 判据适用存疑先查 `references/cases.md` 先例,仍拿不准就停下问(摆选项和推荐),零静默裁定
5. 收尾 grep 四查,模式与豁免见 `references/syntax.md`:避用词、记号标点、墓志铭(交付文档)、悬空引用
6. 呈审前逐句自检:这句在指挥谁/黑话翻译没/记号扫没;不因无负样本跳过

执行流程完成判据:零无理由改动;零静默裁定;四查全过;自检三项过。

## 信息路径模型(动笔前判一次)

**判读者**(agent 向文档):常驻上下文(CLAUDE.md/AGENTS.md,每次会话全文在场)受行数硬约束,收录标准是删了会致 agent 出错的才留;代码可推导/目录树/文件清单/频繁变化的信息全删。按需文档(spec/契约/plan,运行时才读)写全量细节,常驻侧只留一行索引和触发描述。按需细节塞常驻,每次会话白付 token;常驻规则藏按需,agent 可能根本不读。@ 导入不省上下文,按需加载靠运行时 Read。

**判声部**(逐句问"这句在指挥谁"):行为指令句(停下问人/必落审计/只在后端)只住 AGENTS.md——重复即双活,双活必漂移。人读文档零 agent 指令句:行为规则句删或归 AGENTS;信息句(落点在哪/以官方现行命令为准)正常写,人 agent 都能读。同一流程事实双渲染合法:人声版写"你确认后 commit",agent 声版写"停下汇报、人确认后 commit",每个渲染只对本角色说话,改事实时两处同批。不混声不越界。

**写作杠杆**(泛化自 agent 文档写作方法论,两类文档通吃):

- **双预算**:每份文档和指针要么花 agent 的 context load(常驻材料的 token 与注意力),要么花人的 cognitive load(知道有哪些文档、何时读哪个)。经指针才读的材料免 context load,只付指针自身一行;完全无指针的材料全靠人脑索引。投放判断:常驻判据看 agent 会不会错,人向索引看人需不需要判断力。
- **指针措辞定触发**:指针前置于行首触发词,一个分支一个触发词,同义触发词合并;必读材料配弱措辞指针属于缺陷,先改措辞,改不动再内联。指针措辞比目标更决定 agent 何时去读。
- **信息层级**:文内步骤(有序动作)在最上,文内参考(按需查的定义规则)居中,披露参考(独立文件,靠指针触发才读)在底层。什么内容都内联,顶层臃肿;什么都外推,agent 漏读必需材料。判据:所有分支都要用的内联,只有部分分支到的外推。同文件内一个概念的定义、规则、注意事项归拢同节,不散置。
- **完成判据可检**:每步以"什么算完成"收尾,判据要 agent 能区分完成与未完成;模糊判据招致提前收工。判据同时要有需求量——"每个改动都有去向"比"列出改动"逼出彻底性。
- **正引导**:能用目标行为句写的就不写禁令——禁令把被禁行为拉进注意力,半读半教。禁令只留硬护栏,且配对正向目标。
- **no-op 剪除**:逐句问"删掉这句,agent 默认行为会变吗"——与判据 10 试金石同源;不变就整句删,不削词。环境真源(package.json/config/目录)只缓存"查不到的":约定、原因、坑,可查的复述会过期。
- **行文激活词**:用模型预训练里已有的紧凑概念词做全文锚点(一词一义反复用),不造需要定义的新词;三处展开同一意思的段落,收拢成一个词。

## 核心型录(生成相位用;扫描时加状态列即文档地图)

| 型 | 是什么 | 触发器 | 骨架 |
|---|---|---|---|
| agent 入口(CLAUDE.md/AGENTS.md) | agent 常驻上下文:规则与指针 | 用 coding agent | claude-md.md |
| 架构 spec(HLD) | 系统级机制/参数/边界,只读权威源 | 架构想清楚 | hld-lld.md |
| 实施方案(LLD) | 按端实施:模块/接口/落点 | 对应端开工 | hld-lld.md |
| 接口契约 | 两端消息/端点单源 | 两端分离协作 | contract.md |
| 数据契约 | 字段级单源 | 数据生产者≠消费者 | data-contract.md |
| 术语表 | 一词一权威加避用词表 | 命名分歧出现 | glossary.md |
| 决策记录(ADR) | 一次决策一篇,向前采用 | 架构级决策发生 | adr.md |
| 环境/操作手册 | 怎么跑起来/环境变量 | 有人要跑起来 | env-howto.md |
| 进度/恢复台账 | 会话恢复锚点加增量总表 | agent 跨会话工作 | progress.md |
| README | 人向门面:简介/预览/指路 | 编码完成后建立 | readme.md |
| CONTRIBUTING | 贡献者协作规则 | 团队协作规则成型 | contributing.md |

> 项目特有型(研究记录/UI 参考/备忘录/答辩溯源等)随项目文档地图走(进度台账),不进通用型录。
> 域外型,触发才建:CONTRIBUTING 待 README 协作节挤压时建 · CHANGELOG 待对外发版才建(git tag 即内部替代)· runbook 服务多环境部署 · tutorial 面向外部学习者 · PRD 服务多干系人需求谈判 · RFC 服务团队扩大后的评审 · SECURITY/LICENSE 待开源或公开时建。

## 判据表

| # | 判据 | 实例(反例为主) |
|---|---|---|
| 1 | 元信息清零:版本归 git(tag),文件名与内容零版本,日期只进日志文档 | 反例:头部"v3.1 依据某报告;v3.2 又改某节"式版本链、行内日期核实注、带版本号的文件名 |
| 2 | 括号注两分法:删掉这个词读者会误解吗?会就留(术语/消歧/导航),不会就删(状态/叙事/修辞) | 反例:(定稿)(核心)(已迁出);正例:(C4 Container)并非 Docker 容器,留 |
| 3 | 修饰词无增益:不可证伪赞美词删;有效的限定词只认可数事实(唯一/≤10ms/先X再Y) | 反例:"采集器状态机(核心)" |
| 4 | 三层家用词不释词:术语表只写词是什么和用哪个;spec 只写机制参数;plan/contract 只出现 token 和可执行事实 | 反例:plan 里法规长注、版本考古、指向已迁出表的编号 |
| 5 | 数值路径不复制:注释只留名词;数值/端点单源 spec/契约;单复数与数量不可丢。目录/清单不枚举:给根路径让读者自查,不举例堆砌 | 反例:"端点"单数盖住 3 个端点、注释层复制阈值、正文逐文件枚举目录(ls 可查) |
| 6 | 指针归口:零重复指针——携带本层推不出的新信息的可留(同文档导航/"全量表在X"/"定义源在X"类声明);纯重复头部声明的删;「通用细则见X」类中间层桩禁用,直指文件与节名;悬空指针禁写——指实存物,或等实物落地回填;实例句写接口名与文件路径(可 grep),不写 file:line(钉死实现);失败可恢复性定内联——报错型可指针化,静默型必须内联 | 反例:散置"(机制见 spec §4)"、"通用细则见规范文档"、file.py:123 括注、指向未建文档 |
| 7 | 四病型消歧:被动句→动词句;一词多义→限定;锚点不明→写明起算点;指代不明→写明主体 | 反例:"60s 兜底"(从哪起算)、"常态"两处打架 |
| 8 | 一步搬家:原处删除与落地同一次完成,禁半步迁移;代码注释同属文档面,随文档批同批修不劈批 | 反例:删了兜底句、新家被拦→机制悬空;改文档留注释旧话另批处理 |
| 9 | 调研归宿:编码文档只留结论钉子,"为什么"进进度台账的技术核查记录 | 反例:peer 兼容考古写进实施方案 |
| 10 | 元原则:删"重复的说明",不删"唯一的规格";试金石是删掉后 agent 会被迫猜吗?重复是假缺 | 反例:以"宁冗勿缺"保留重复 |
| 11 | 未实现处置:有固定落点的,在落点注明未实现并指详情落点;无落点的,落待办清单注未实现 | 反例:契约写了协议实现没有,文档不注明;或直接删条目装作没有 |

## soft dependency

无术语表的项目(本 skill 移植他项目时):跳过避用词 grep 并在结果注明"避用词未查(无术语表)",其余判据与流程照常。

## 裁定入档(增长环)

新裁定(驳回或拍板)有两个出口:可泛化(同类问题会再现)的进判据表加行或改行;项目特有且可复用的在 `references/cases.md` 追加一行(问句含可检索关键词,结论先行);一次性决策不入档。同一错误第二次出现才加规则,第一次口头纠正不入档。
用词误用裁定(会话驳回/自查/调研查得训练旧知识)写入该项目术语表(glossary 型文档):正词是名称/术语强约束,只能用这个词;避用列仅收"agent 训练先验会自发产出且产出即错"三类——①机制命名冲突(先验命名与项目机制事实不符)②字段漂移(同义替换致 grep·契约失配)③安全红线·过时事实;旧项目名与项目自造旧词不入(正词强约束已覆盖名称用法,描述性泛称合法;自造词不在阅读域不会自发)。
判据适用存疑先查 `references/cases.md` 先例,再问人。

## 完成判据

- 审查相位:每处修改有一句话理由(判据 2/10 试金石);零悬空引用、零半步迁移;grep 四查零命中
- 生成相位:缺项清单获点头;产物过骨架全节和判据表;人向产物另过 human-style.md 完成判据
