# 文档规范判据(交付文档写/改/审 + 缺位生成)

> 通用文档理论=mattpocock-skills:writing-for-agents,不在此复制;本 skill 只装本项目实证裁定。判据完整正反例与来历=`docs/doc-standards-research-v1.md`(存档,不再更新);现行操作以本文件十判据表为单源;裁定先例与增补=`references/cases.md`;骨架库=`references/type-skeletons/`;人向文风=`references/human-style.md`。

## 适用分叉

先判性质再套判据:**交付文档**(架构 spec / 前后端方案 / 契约 / CLAUDE.md)受十判据约束;**日志文档**(ARCHITECTURE_PROGRESS、docs/ 研究 ADR)日期与叙事合法,只受避用词约束。

## 相位分叉

再判相位:**目标文档不存在**→走生成流程;**已存在要写/改/审**→走执行流程(十判据逐处裁定)。

## 生成流程(文档缺位时)

1. 扫触发器:问两个问题——项目什么状态?谁要用?——对照下方核心型录逐型判触发
2. 呈缺项清单:一行一型,附触发器命中理由;状态以文件存在性核验(ls),不凭记忆
3. 用户点头后才动笔,不静默铺文档
4. 照 `references/type-skeletons/` 对应骨架逐份生成;人向文档过受众分叉
5. 十判据自查收尾——生成产物同样受判据约束

done=缺项清单已呈报并获点头;每份产物过骨架全节;grep 三查零命中。

## 核心型录(生成相位用;扫描时加状态列即文档地图)

| 型 | 是什么 | 触发器 | 骨架 |
|---|---|---|---|
| agent 入口(CLAUDE.md/AGENTS.md) | agent 常驻上下文:规则+指针 | 用 coding agent | claude-md.md |
| 架构 spec(HLD) | 系统级机制/参数/边界,只读权威源 | 架构想清楚 | hld-lld.md |
| 实施方案(LLD) | 按端实施:模块/接口/落点 | 对应端开工 | hld-lld.md |
| 接口契约 | 两端消息/端点单源 | 两端分离协作 | contract.md |
| 数据契约 | 字段级单源 | 数据生产者≠消费者 | data-contract.md(占位) |
| 术语表 | 一词一权威+避用词表 | 命名分歧出现 | glossary.md |
| 决策记录(ADR) | 一次决策一篇,向前采用 | 架构级决策发生 | adr.md |
| 环境/操作手册 | 怎么跑起来/环境变量 | 有人要跑起来 | env-howto.md |
| 进度/恢复台账 | 会话恢复锚点+增量总表 | agent 跨会话工作 | progress.md |
| README | 人向门面:简介/预览/指路 | 编码完成后建立 | readme.md |
| CONTRIBUTING | 贡献者协作规则 | 团队协作规则成型 | contributing.md |

> 项目特有型(研究记录/UI 参考/备忘录/答辩溯源等)随项目文档地图走(PROGRESS §二),不进通用型录。
> 域外型,触发才建:CONTRIBUTING=README 协作节挤压 · CHANGELOG=对外发版(git tag 即内部替代)· runbook=多环境部署 · tutorial=有外部学习者 · PRD=多干系人需求谈判 · RFC=团队扩大需评审 · SECURITY/LICENSE=开源或公开。

## 受众分叉(动笔前判一次)

**谁读?** agent 读(spec/plan/契约/CLAUDE.md)→十判据全量+本 skill 全流程;人读(README/操作手册/教程/答辩)→判据 5(数值单源)与 6(指针归口)照用——防漂移不管文风;文风走 `references/human-style.md`(保真合同最高律+四型语气卡+负面模式清单)。

## 执行流程(审查相位)

1. 定性质:交付 or 日志。done=性质已定
2. 逐段套十判据分删/留/改写,每处改动记一句话理由——**删了行为会变吗?** 不变=删;会迫使 agent 猜=必留。done=零无理由改动
3. 存疑→停下问(摆选项+推荐),不静默裁定。done=零静默裁定
4. 一步搬家:原处删除与落地同一次完成,禁半步迁移(半步=机制悬空)。done=删除与落地同 commit
5. grep 验证:CONTEXT.md 避用词零命中 · 版本/日期/墓志铭零残留(交付文档) · 悬空引用零。done=三项全过

## soft dependency

无 CONTEXT.md 的项目(本 skill 移植他项目时):跳过避用词 grep 并在结果注明"避用词未查(无术语表)",其余判据与流程照常。

## 十判据

| # | 判据 | 实例(反例为主) |
|---|---|---|
| 1 | 元信息清零:版本=文件名自带,修订叙事归 git,日期只进日志文档 | 反:头部"v3.1 依据…;v3.2=…"、行内"2026-08-22 核实" |
| 2 | 括号注两分法:删掉这个词读者会误解吗?会→留(术语/消歧/导航),不会→删(状态/叙事/修辞) | 反:(定稿)(核心)(已迁出);正:(C4 Container)≠Docker 容器,留 |
| 3 | 修饰词无增益:不可证伪赞美词删;有效=可数事实限定词(唯一/≤10ms/先X再Y) | 反:"采集器状态机(核心)" |
| 4 | 三层家用词不释词:CONTEXT=词是什么+用哪个;spec=机制参数;plan/contract=只出现 token+可执行事实 | 反:plan 里法规长注、版本考古、指向已迁出表的编号 |
| 5 | 数值路径不复制:注释只留名词;数值/端点单源 spec/ws-contract;单复数与数量不可丢 | 反:"端点"单数盖住 3 个端点、注释层复制阈值 |
| 6 | 指针归口:零重复指针——携带本层推不出的新信息的可留(同文档导航/"全量表在X"/"定义源在X"类声明);纯重复头部声明的删;入口=CLAUDE.md 常驻指针(带触发)+文档头权威源行;失败可恢复性定内联——报错型可指针化,静默型(--force 装过/运行时黑屏)必须内联 | 反:散置"(机制见 spec §4)" |
| 7 | 四病型消歧:被动句→动词句;一词多义→限定;锚点不明→写明起算点;指代不明→写明主体 | 反:"60s 兜底"(从哪起算)、"常态"两处打架 |
| 8 | 一步搬家:原处删除与落地处同一次落地 | 反:删了兜底句、新家被拦→机制悬空 |
| 9 | 调研归宿:编码文档只留结论钉子,"为什么"进 PROGRESS 技术核查记录 | 反:peer 兼容考古写进 frontend-plan |
| 10 | 元原则:删"重复的说明",不删"唯一的规格";试金石=删掉后 agent 被迫猜吗?重复=假缺 | 反:以"宁冗勿缺"保留重复 |

## 完成判据

- 审查相位:每处修改有一句话理由,且过第 2/10 条试金石;第 5 步三项 grep 全过;零悬空引用、零半步迁移
- 生成相位:缺项清单获点头;产物过骨架全节+十判据;人向产物另过 human-style.md 完成判据

## 裁定入档(增长环)

新裁定(驳回/拍板)→**双出口**:可泛化→十判据表加行或改行;项目特有→`references/cases.md` 追加"问→裁定"一行。判据适用存疑→先查 `references/cases.md` 先例,再问人。skill 迁用户级时 cases.md 留项目,泛化出口不变。
